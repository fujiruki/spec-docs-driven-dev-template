# 要望の入力箱 (requests.md)

運用開始日: YYYY-MM-DD

思いついた要望を、雑な言葉のまま書く。ここは未整理・仕様確認中の入力箱である。

会話で要望を受けた指揮AIも、仕様の話を始める前に原文をここへ追記する。仕様化を始める時に `SDDD.md` の規則でR-IDを付ける。仕様が確定した要望は、原文・要望ID・仕様リンクを [requests_log.md](requests_log.md) へ記録してから、このファイルの該当項目だけを削除する。

---

## 発注者向けの書き方

形式は自由。箇条書きで十分。

```markdown
- ログイン機能にGoogleアカウント対応を追加してほしい
- ダッシュボードに月次売上グラフを表示したい
```

優先度を付けたい場合:

- **【高】** 業務に支障がある / バグ / 納期が迫っている
- **【中】** あると便利 / 改善要望
- **【低】** いつかやりたい / アイデア段階

---

## AIへの絶対ルール

1. 会話で受けた要望も、まず原文のままここへ記録する
2. 仕様化を開始するときは `SDDD.md` の採番規則で `R-0001` のような要望IDを付ける。原文を要約・書き換えない
3. 仕様が未確定の要望を削除・他要望へ統合・見送りにしない。判断が必要なら発注者へ聞く
4. 仕様が確定した時、先に `requests_log.md`、`spec/`、タスクを更新してから該当項目だけを移動する
5. ファイル全体をクリアしない。黙って消さない
