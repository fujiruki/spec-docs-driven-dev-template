# 運用自動化と索引

同じ転記・確認・検索を繰り返す、または記録漏れが起きやすい場合、指揮AIは小さな自動化を提案または作成してよい。

## 境界

- Markdownの要望・仕様・台帳は正本。SQLite、HTML、ダッシュボードは原則として再生成できる索引・表示にする
- 自動化は可逆で、失敗しても手作業へ戻れるようにする
- 外部サービス、課金、認証情報、権限、公開範囲を変える場合は発注者に確認する
- `.sddd/` とCodeGraphの `.codegraph/` は再生成可能なローカルデータとして既定でGit管理外にする。共有する設定や出力が必要な時だけ、対象・理由・更新者をチームで決める

## 候補

- 要望ID、spec、タスク、Issue、PRのリンク検査
- 引継書・コンテキストパックの下書き
- MarkdownからSQLite索引・HTMLダッシュボードを生成
- CodeGraphなどでコード影響範囲の候補を検索し、実際に読むファイルと検証項目をタスクへ記録

自動化を作る前に、目的、入力、出力、正本、失敗時の戻し方を短く記録する。

## CodeGraph連携（推奨）

[CodeGraph](https://github.com/colbymchenry/codegraph) は、コードの依存関係と変更影響を調べるローカルのコード索引である。複数モジュールをまたぐ変更、既存コードの変更、並列実装、レビューでは優先して使う。

1. 要望ID、仕様、受け入れ条件を読む
2. CodeGraphで入口、呼び出し関係、影響候補を調べる
3. 実際に変更・確認するファイル、リスク、テスト項目をタスクまたはPRへ記録する
4. 実装後は仕様・受け入れ条件・テスト結果で完了を確認する

CodeGraphの結果は影響調査の補助であり、仕様の正本でも完了根拠でもない。
