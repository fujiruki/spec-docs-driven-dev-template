# フォルダ構成

> 各情報の正本を一つに決め、AIと人が必要な範囲だけ読める構成にする。

## 基本構成

```
SDDD.md                  <- ツール非依存の正本ルール
AGENTS.md                <- 汎用AI向けアダプター
CLAUDE.md                <- Claude Code向けアダプター（使う場合）
.agents/skills/          <- Codex向けの再利用可能な作業Skill
  kaigi/                 <- 単一コンテキストの軽量専門家会議
  kaigi2/                <- 独立Agentによる高品質専門家会議
docs/
  SPEC.md              <- 現行仕様への短い入口
  requests.md          <- 未整理・仕様確認中の要望
  requests_log.md      <- 仕様確定後の全要望台帳
  spec/                <- 現在有効な仕様
  handover/            <- 担当交代時の再開記録
  automation.md        <- 任意の自動化・索引の方針
  collaboration.md     <- 任意の並列・GitHub協業の方針
task.md                <- 小規模時の実装・検証計画
tasks/                 <- 並列時の要望ID別タスク（任意）
.sddd/                 <- SQLite索引など再生成できる補助データ（任意・原則Git管理外）
.codegraph/            <- CodeGraphのローカル索引（任意・原則Git管理外）
```

## 正本の境界

| 情報 | 正本 | 補助的な表示・索引 |
|:--|:--|:--|
| 仕様化前の要望 | `requests.md` | — |
| 要望の原文・経緯・状態 | `requests_log.md` | SQLite索引、HTML一覧 |
| 現在有効な振る舞い | `spec/*.md` | `SPEC.md`、HTML仕様ポータル |
| 実装・検証の作業 | `task.md` または `tasks/R-0001.md` | ダッシュボード、GitHub Issue |
| チームの担当・議論・PR状態 | GitHub Issue / PR | GitHub Project |
| コードの実装結果 | GitコミットとPR | CodeGraphなどの索引 |

HTML、SQLite、ダッシュボード、CodeGraphは便利だが、Markdownの要望・仕様を勝手に上書きする正本にはしない。

## 要望台帳のライフサイクル

### `requests.md`: 入力箱

発注者は思いつきを自由に書く。会話で要望を受けた指揮役も、まずここへ原文を記録する。仕様化を開始する時は `SDDD.md` の採番規則でR-IDを付ける。原文を要約で置き換えない。

仕様確認中は `requests.md` に残す。仕様を確定できない場合も、黙って消さない。

### `requests_log.md`: 全要望の台帳

仕様が確定したら、次の順で処理する。

1. `requests_log.md` に要望ID、原文、受付日、仕様反映先、受け入れ条件、初期状態 `仕様化済み` を記録する
2. `spec/` と `SPEC.md` を更新し、要望IDを記す
3. `task.md` または `tasks/R-0001.md` に実装・検証タスクを作る
4. 記録を確認してから、`requests.md` の該当項目だけを削除する

実装開始・検証開始・完了・保留・見送り・取り下げ・他要望への統合が起きたときは、同じ台帳記録の状態と根拠を更新する。`他要望への統合` には統合先R-IDと理由を必ず書く。コードがマージされたことは、通常 `完了` の根拠であって要望状態の「統合」ではない。記録を消して作り直さない。

### `spec/`: 現在の正

`spec/` には現在有効な仕様だけを置く。各追加・変更箇所は、可能な限り要望IDへリンクする。古い要望の理由や検討案は台帳または変更履歴に残し、現行仕様へ混ぜない。

## 大きくなった時の分割

`requests_log.md` が大きくなり、毎回の読み込みに不向きになったら、ファイルを短い索引にして詳細を分ける。

```
docs/
  requests_log.md       <- R-0001、状態、短い概要、詳細リンクだけ
  requests_log/
    R-0001.md           <- 原文、判断、仕様、検証、PR
```

AIはまず索引を読み、必要な要望IDだけを開く。SQLiteはこのMarkdown群を検索・集計する再生成可能な索引として、必要になった時だけ導入する。
